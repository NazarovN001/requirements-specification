# Requirements Engineering — Инженерия требований к ПО

## О проекте
Учебный проект Школы 21 (индивидуально).  
Провёл полный цикл работы с требованиями: от выявления потребностей стейкхолдеров до документирования требований, построения контекстных диаграмм и моделирования процессов as is / to be.

## Моя роль
- Выявил и проанализировал потребности стейкхолдеров
- Построил контекстную диаграмму для определения границ системы
- Смоделировал процессы в состояниях as is (как есть) и to be (как будет)
- Разработал таблицы входных/выходных потоков данных
- Подготовил глоссарий терминов и каталог стейкхолдеров

## Выполненные задачи

### Задание 1: Анализ требований к системе
- Идентифицировал роли стейкхолдеров и их действия в текущем состоянии (as is)
- Выявил проблемы текущего состояния для каждой роли
- Построил контекстную диаграмму с внешними сущностями и потоками данных
- Спроектировал целевое состояние (to be) с решением выявленных проблем
- Определил входные/выходные потоки данных между системой и внешними сущностями
- Подготовил глоссарий терминов предметной области

## Результаты
- Таблица ролей и их действий as is с выявленными проблемами
- Контекстная диаграмма системы
- Таблица действий to be с описанием решения проблем
- Таблица входных/выходных потоков данных
- Глоссарий терминов
- Актуализированный каталог стейкхолдеров

## Инструменты
- Context Diagram (контекстная диаграмма)
- AS-IS / TO-BE моделирование
- Stakeholder Analysis (анализ стейкхолдеров)
- Data Flow Diagram (потоки данных)
- Excel/Google Sheets для таблиц
- Draw.io / Lucidchart для диаграмм

## Структура проекта
- `src/ex00_DELO_asis.xlsx` — роли и действия as is с проблемами
- `src/ex01_DELO_context.png` — контекстная диаграмма

- `src/ex03_DELO_streams.xlsx` — входные/выходные потоки данных

## Ключевые навыки
- Выявление требований через анализ потребностей стейкхолдеров
- Моделирование процессов в нотации as is / to be
- Определение границ системы через контекстные диаграммы
- Документирование требований в структурированном виде
- Анализ потоков данных между системой и внешними сущностями
- Управление терминологией через глоссарий проекта
